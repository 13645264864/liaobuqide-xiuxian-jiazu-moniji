# 真人家族文字修仙：首版开发任务

状态：任务计划待确认，尚未开始实现。需求见 `requirements.md`，方案见 `design.md`。勾选表示真实完成并验证，不表示已经讨论过。

## 第一阶段：可安装、可登录、真人血脉跑通

- [ ] T1. 建立独立项目与双端外壳。
  - React/TypeScript/Vite 界面，Capacitor Android 外壳，四个主入口和右上角聊天入口。
  - 新项目不放进其他游戏运行场景，不复用其他游戏包名或签名。
  - 检查现有 Android SDK/JDK 与所选 Capacitor/Gradle 版本的兼容性；现有工具包含 JDK 17 和 Android 35，不能假定新工程无需补齐工具。
  - 交付可打开的网页与可构建的 Android 工程；优先生成早期调试 APK 验证安装和网页内容显示。
  - 关联需求：1、15。

- [ ] T2. 准备独立数据资源与真实账号登录。
  - 确定使用新 CloudBase PG 环境还是现有环境的隔离业务表，明确对应账号隔离；如需创建付费资源，先给出套餐与费用方案。
  - 检查 provider、真实注册 API、Publishable Key、网页与 Android 来源授权。
  - 先通过版本迁移建立角色、创世计数、家族、谱系、成员、道侣、名额与操作回执，再连接界面。
  - 用户身份为 text UID，建立 RLS/受控 RPC 权限，客户端不直接写属性/族长/亲缘。
  - 验收：真实账号在 Android 与网页登录后读取同一角色；其他账号不能修改其数据。
  - 关联需求：1、2、3、8。

- [ ] T3. 创世入世、家族创建与出生选择。
  - 实现前 50 名创世资格、首任原始族长、加入原始家族与独立建族。
  - 前 50 名先祖背景、注册计数时点先确定，不将未确认的建议直接实施。
  - 实现家族简介、初始名额优先排序、推荐/随机匹配、性别与灵根接纳规则。
  - 验收：第 50/51 名边界正确，并发不会多发创世资格；无名额时显示候补状态。
  - 关联需求：2、3、5。

- [ ] T4. 真人道侣与子女出生。
  - 双方接受婚约后创建道侣关系，并在同一事务生成 2 个初始子女名额。
  - 初始两个名额领取无需父母审批；更多子女需要父母同意，不自动无限补充。
  - 实现前明确额外接纳是开放额外名额还是逐人批准，以及是否双方均需同意。
  - 子女可以选择父母任一家族；同一资格不能因有两个家族选项被重复领取。
  - 展示家庭与族谱；分家改变当前家族，不改写父母。
  - 成婚礼金、已故父母支付来源与近亲婚配规则在实现对应步骤前确认。
  - 验收：不同真实账号结为道侣，第三个账号成为子女；初始两个无需审批，第三个不能绕过同意；同时领取最后一个资格只成功一人。
  - 关联需求：3、4、5。

第一阶段可玩成果：用户拿到早期 APK 和本地网页入口，用多个账号完成创世、建族、结为道侣和子女出生。此时不宣称修炼或守城已完成。

## 第二阶段：文字修炼与战斗循环

- [ ] T5. 闭关、宗祠、物品与突破试炼。
  - 服务端时间计算闭关收益，位置变化分段结算；重试不重复领取。
  - 宗祠加成、丹田容量和实际灵气分别保存，每颗扩容丹增加 0.5 个百分点。
  - 先实现一段境界与一场判定妖魔，头像动作和实际战斗日志对应。
  - 大境界品级判定方式、失败损失、扩容继承及复活货币在实现前明确，数值放入配置。
  - 验收：实际收益读回数据库；扩容消耗与加成真实生效；突破胜负/损失仅结算一次。
  - 关联需求：6、7、8、10。

- [ ] T6. 一次完整小兽潮与家族合作。
  - 后台任务生成并推进小兽潮，有限战略点，战斗/修补/愿力三类行动。
  - 在线愿力通过心跳租约判断，Android 切后台或断网后自动过期。
  - 敌方占据超过 50% 战略点后失守；实现危机通知、求援和带抵达时间的支援。
  - 在实现前明确兵力计算与五倍夺回规则，避免人数和战力混用。
  - 验收：无人开界面仍推进事件；真实成员行动影响进度，50%/超过 50% 的边界正确，支援不会瞬间到场。
  - 关联需求：8、9、10、12。

## 第三阶段：社交、地图与交付

- [ ] T7. 聊天、家族管理与基础出行。
  - 世界、家族、家庭、私聊；陌生人未回复前一句问候，回复后开放会话。
  - 师徒保留入口，未实现时明确提示；家族简介和接纳策略由真实族长编辑。
  - 基础州内地点与旅行时间，公开世界背景、未开放区域与活动说明。
  - 「更多」提供其他游戏入口，外部入口地址配置后才开放跳转。
  - 验收：家族/家庭消息不越权；刷新不能多发问候；网页与 Android 能一致处理聊天和出行。
  - 关联需求：1、3、5、12、14。

- [ ] T8. 首版联合验证、签名 APK 与网页发布准备。
  - TypeScript、构建、关键事务/并发检查、真实浏览器流程和 Android 安装验证。
  - CloudBase 代码审查，修复权限、登录、数据库与 SDK 问题。
  - 新游戏独立发布签名与包名，保留签名身份；完善账号管理、隐私说明和联网权限。
  - 发布前给出可审核的成品、验证结果与目标地址；未执行部署时不声称已有公网网页。
  - 交付 APK、网页构建产物、本地运行命令、操作说明与验证报告；公网部署单独记录结果。
  - 关联需求：1、8、15。
